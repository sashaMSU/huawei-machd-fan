# Карта памяти и происхождение данных / provenance

## Источник данных

Реверс-инжиниринг дампа BIOS 1.67. В таблицах ACPI ничего полезного не было, там стандартный метод _FSL пустой.

Дамп могу прислать по запросу.

## ACPI-транспорт

```text
\_SB.PC00.LPCB.H_EC.RDER(offset)
\_SB.PC00.LPCB.H_EC.WTER(offset, byte)
```

Это внутренний расширенный протокол. Смещения **не являются адресами обычного
256-байтного ec_sys**. Для известной структуры EC абсолютный адрес имеет вид
`0x80000 + offset`; никаких произвольных адресов пользователю CLI не предоставляет.

[acpi_call](https://github.com/nix-community/acpi_call) предоставляет
`/proc/acpi/call`; его общий буфер ответа не делает несколько независимых
пользовательских процессов безопасными. Блокировка файла защищает только
сотрудничающие экземпляры этой программы.

`RDER` может вернуть `0xFF` и как данные, и при тайм-ауте внутри AML. Один байт
`FF` сам по себе не доказывает ошибку. Поэтому проверяются структура и диапазоны,
а после записей — прочитанные значения. Синтаксически неверный ACPI-ответ отвергается.

## Проверяемая структура

| Смещение RDER | Смысл |
|---|---|
| `0x0700..0x0702` | Версия EC: `01 43 00` |
| `0x3164` | Указатель конфигурации: `0x8403C` |
| `0x403C..0x4213` | 472-байтная конфигурация |
| `0x40A4` | Sensor IDs: `8,0,1,10,11,9` |
| `0x40BC` | Указатели пяти строк порогов |
| `0x40D0 + 24*i` | Шесть float32 в строке порогов |
| `0x4148` | Указатели трёх массивов RPM |
| `0x4154 + 24*i` | Шесть uint32 пределов RPM |
| `0x419C`, `0x41B4` | Цели low / high, по шесть float32 |
| `0x41CC`, `0x41E4`, `0x41FC` | Векторы Kp / Ki / Kd |
| `0x3174` | Указатель состояния: `0x84214` |
| `0x4258` | Массив фильтрованных температур |
| `0x422C` | Внутреннее задание первого вентилятора |
| `0x4234`, `0x4238`, `0x423C` | High / enabled / step |
| `0x2A00..0x2A03` | Два тахометра uint16 |
| `0x2A04`, `0x2A05` | Два командных байта, единица 100 RPM |
| `0x2C20` | Проверка битов ручного режима маской `0x0A` |

Все многобайтовые числовые поля здесь little-endian. Фиксированные указатели,
счётчики и три служебных канала проверяются, а не переписываются. Скрипт не
пытается искать другую структуру по эвристике или «похожим» адресам.

## Что именно записывается

Только поля, перечисленные в `FIELDS`, только внутри известной конфигурации.
Они занимают 240 из 472 байт; остальные 232 байта используются как контроль
layout. Ki/Kd допускаются только нулевые. В пользовательском профиле из этого
репозитория отличаются **14 байтов** от заводского блока:
11 байтов температурных параметров, 2 байта минимума RPM, 1 байт скорости снижения.

`plan_writes` сначала строит весь план без аппаратных записей. Проверяются
промежуточные числа/отношения порогов. При смене экспоненты float промежуточное
значение может быть ниже обоих конечных; для фильтра временная сумма весов может
быть меньше 1. После каждой записи — чтение байта, после применения — всего блока.
**Это не транзакция**: EC может увидеть промежуточную конфигурацию.

Предварительное повторное чтение и проверки версии перед каждым байтом снижают
риск гонки, но не устраняют возможность EC reset/действия другого процесса между
операциями. Нет утверждения о корректности произвольных сочетаний коэффициентов
или о гарантированном восстановлении после аппаратного сбоя.

## Статус подтверждения

- Параметры заводского блока: источник — реальное чтение владельца до изменений.
- Запись профиля +5 в предыдущих испытаниях: сообщалась и журналировалась владельцем.
- Полные условия регулятора: рабочая интерпретация предыдущего анализа прошивки;
  исходная дизассемблировка в этот репозиторий не включена.
- Новая реализация записи, журналирования, CLI и упаковки: тесты на модели памяти.

Не расширяйте поддержку только по совпадению названия MateBook или ESRT GUID.
