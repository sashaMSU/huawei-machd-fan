# Проверки публикационной сборки

Дата подготовки: **2026-11-16**. Локально использовался **Python 3.13.5 / Linux**.

```bash
python3 huawei_fan_table.py check
python3 -m unittest discover -s tests -v
bash -n install.sh uninstall.sh
```

Локально прошли **29 тестовых методов**. Внутри них есть дополнительные случаи:
ошибки до/после каждого из 14 записываемых байтов, отказ в каждой позиции
восстановления, проверка каждого неизменяемого байта и различные неверные TABLE.
Число методов не следует смешивать с числом внутренних сценариев.

Проверено:

- точное соответствие поставляемой TABLE заданию владельца;
- независимые FACTORY, заголовок и массивы из обезличенного исходного снимка;
- применение, повтор без записей, восстановление и повтор после сброса EC;
- допустимые промежуточные конфигурации при побайтовом изменении;
- продолжение или восстановление после частичных записей без recovery-файла;
- отказ от записи при чужой плате/версии/указателях/структуре/ручном режиме;
- высокая или недостоверная измеренная температура не останавливает настройку;
- нулевые RPM допустимы; журнал различает target/command/rpm/limit;
- блокировка второго экземпляра;
- реальные SIGTERM и SIGINT в дочернем процессе с моделью EC, включая наследуемую
  блокировку SIGINT; доставка сигнала вызывает проверенный возврат FACTORY;
- синтаксис двух shell-скриптов;
- локальная проверка unit-файла через `systemd-analyze verify` (код возврата 0).

Workflow GitHub Actions настроен на Python 3.10, 3.12, 3.13 и 3.14. До публикации
он **не запускался на GitHub**; это план проверки совместимости, не результат.

Юнит проверяется установщиком через `systemd-analyze verify` в целевой системе.
Наличие `acpi_call` и его загрузка не проверяются GitHub-тестами.
