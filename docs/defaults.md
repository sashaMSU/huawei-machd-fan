## Полная заводская TABLE

```python
TABLE = {
    "step0": (75, 47, 63),
    "step1": (90, 50, 68),
    "step2": (95, 54, 75),
    "step3": (100, 56, 80),
    "step4": (102, 60, 85),
    "low": (75, 47, 63),
    "high": (90, 50, 68),
    "kp": (5, 3, 3),
    "ki": (0, 0, 0),
    "kd": (0, 0, 0),
    "on": (43, 50),
    "off": (40, 47),
    "switch": (47, 50),
    "rpm0": (3600, 3900, 4450, 5000, 5600, 7300),
    "rpm1": (4400, 5000, 5500, 6100, 7000, 7600),
    "rpm2": (4200, 4600, 5400, 6400, 7100, 7800),
    "preset": 1,
    "minimum_rpm": 4100,
    "filter": (0.98, 0.02),
    "slew": (50, 20),
}
```

Копируйте её на место пользовательской `TABLE`, а не поверх `FACTORY`.

## Важные смысловые различия

- `step0` — порог между ступенями **0 и 1**, не RPM ступени 0. В активном наборе
  `rpm1` первой ступени соответствует предел 5000, нулевой — 4400.
- `step` — промежуточный потолок расчёта. Позднее ограничение скорости изменения
  может временно оставить задание выше нового потолка, а минимум — выше значения
  из одного из других RPM-наборов.
- `low/high` — цели температуры; `switch` выбирает весь вектор одновременно.
  Это не режимы питания KDE/Windows и не низкие/высокие обороты.
- Минимум 3100 — не приказ всегда держать 3100. В известном парном режиме второй
  вентилятор получает команду ниже на 200 RPM, но измеренные RPM могут отличаться.
- `filter` влияет на нагрев **и** остывание. `slew` ограничивает максимально
  разрешённое изменение, а не гарантирует его на каждом расчёте.
- Диапазоны `validate()` проверяют формат и правдоподобность конфигурации. Они не
  утверждают, что любые прошедшие проверку температуры безопасны для компонентов.
- Изменение многобайтовых полей неатомарно. Для пары весов фильтра промежуточная
  сумма может быть меньше 1; нельзя трактовать такую запись как одновременную.

## Ограничение I/D в публикационной версии

Адреса `ki/kd` и нулевые заводские значения известны. Но эта сборка не переносит
непроверенное управление историей интегратора/производной. Поэтому ненулевые
коэффициенты отвергаются до записи, в том числе если они уже присутствуют в EC.
Это осознанное ограничение этой новой сборки по сравнению с поздними
экспериментальными версиями из обсуждения. Для заданной пользователем TABLE
поведение не меняется: в ней `ki=kd=0`.
