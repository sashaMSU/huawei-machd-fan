# Как связаны low/high, step и RPM

Это рабочая интерпретация регулятора **NB2757 EC 1.67**, использовавшаяся в
предыдущих экспериментах. Полный исходник прошивки не опубликован. Параметры
проверяются по [снимку конфигурации](evidence/ec167-factory.json); этот снимок
сам по себе не доказывает все условные переходы исполняемого кода.
Отдельные переходы ранее согласовались с журналами владельца. Включённые тесты
проверяют **Python и карту памяти**, а не эмулируют всю прошивку.

## Последовательность

```text
Сырые температуры -> filter -> выбор набора целей low/high
                             -> кандидаты задания по каналам
                             -> максимум кандидатов
                             -> предел активного RPM-пресета для step
                             -> slew
                             -> minimum_rpm либо 0 при выключенном вентиляторе
                             -> низкоуровневое управление вентилятором
```

`step` вычисляется из тех же фильтрованных температур, но отдельно от кандидатов
оборотов. Поэтому `step=1` не обязывает EC держать 5000 RPM.

## Температуры и сглаживание

Порядок каналов в таблице: CPU EC/TP00, SEN1, Charger/SEN2. CPU EC нельзя
непосредственно подменять `coretemp Package id 0`. Физическое положение SEN1
не установлено. В полной конфигурации есть ещё три постоянных канала
38, 38, 30 °C; их пороги и цели 999 °C оставлены неизменными.

При заводских весах:

```text
T_filtered(new) = 0.98 × T_filtered(old) + 0.02 × T_raw
```

Это формула на обновление регулятора EC, не на пятисекундный проход Python.
Точный период расчёта EC в этой публикационной сборке не измерен.

## Включение / остановка

Для поставляемой TABLE:

```text
если выключены: включить при SEN1 >= 48 ИЛИ Charger >= 50
если включены: выключить при SEN1 < 45 И Charger < 47
иначе: сохранить состояние
```

Заводские пороги SEN1 — 43/40; Charger — те же 50/47. CPU в этой конкретной
ветке напрямую не участвует. Это не утверждение об отсутствии других защит EC.

## Наборы целей

Для поставляемого профиля:

```text
SEN1 > 55  -> high = (90, 55, 68)
SEN1 <= 52 -> low  = (75, 52, 63)
между границами -> прежний набор
```

SEN1 переключает цели **всех каналов**. Более высокий верхний порог `switch`
дольше удерживает `low`, где цели CPU/Charger ниже. Это может увеличить запрос
охлаждения относительно более раннего выбора `high`.

## Ступени

При нагреве переход вверх требует превышения номинального порога на **>0.5 °C**
хотя бы одним каналом. При охлаждении для перехода вниз нужны значения **<порог−0.5**
по всем учитываемым каналам. За расчёт ступень меняется на одну. У постоянных
каналов порог 999 °C, поэтому фактически решение определяется тремя живыми.

Полные границы для поставляемого профиля:

| Переход вверх (ИЛИ) | CPU EC | SEN1 | Charger |
|---|---:|---:|---:|
| 0→1 | >75.5 | >52.5 | >63.5 |
| 1→2 | >90.5 | >55.5 | >68.5 |
| 2→3 | >95.5 | >59.5 | >75.5 |
| 3→4 | >100.5 | >61.5 | >80.5 |
| 4→5 | >102.5 | >65.5 | >85.5 |

| Переход вниз (И) | CPU EC | SEN1 | Charger |
|---|---:|---:|---:|
| 1→0 | <74.5 | <51.5 | <62.5 |
| 2→1 | <89.5 | <54.5 | <67.5 |
| 3→2 | <94.5 | <58.5 | <74.5 |
| 4→3 | <99.5 | <60.5 | <79.5 |
| 5→4 | <101.5 | <64.5 | <84.5 |

Границы CPU выше 100 °C здесь — **данные конфигурации**, не рекомендуемая
температура эксперимента. В этой службе нет температурного порога аварийного выхода.

## Расчёт задания при нулевых I/D

Рабочая модель для известных коэффициентов:

```text
error_i = filtered_temperature_i - selected_target_i
если -0.5 < error_i < 0.5: error_i = 0
candidate_i = clamp(previous_target + Kp_i × error_i, 0, 10000)
requested = max(candidate_i)
```

Это **прибавка к предыдущему заданию**, а не классическое статическое P-управление.
Далее применяются предел ступени, ограничение изменения `slew` и условный минимум.
Из-за `max` один канал около своей цели может удерживать RPM, хотя остальные остыли.

В `preset=1` пределы ступеней 0…5: 4400, 5000, 5500, 6100, 7000, 7600.
При `target=3100` переход потолка с 4400 на 5000 сам по себе не изменит задание.
При понижении потолка с 6100 до 5500 ограничение снижения 60 может дать сначала
6040, а не мгновенно 5500. Физические RPM меняются отдельно от расчётного задания.

## Диагностика медленного затихания

Сначала сравните `target`, `command`, `rpm` и фильтрованные температуры.

- Температура `coretemp` упала, фильтрованные EC ещё высоки: влияет задержка датчиков/фильтра.
- EC уже просит снизить задание, но оно спускается по максимальному шагу: влияет `slew`.
- Один канал остаётся у цели или выше: его запрос может удерживать обороты.
- Задание снизилось, тахометр нет: исследовать нижележащее управление, не менять `step` вслепую.

Включение I/D не является подтверждённым решением: их ненулевая работа в этой
сборке не поддерживается. Интервал логирования не задаёт скорость расчётов EC.
